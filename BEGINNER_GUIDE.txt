SLUGGER NEO v0.5.3 — BEGINNER GUIDE

WHAT CHANGED
- Automatic touch-device detection for phones/tablets.
- On-screen movement joystick with analog movement strength.
- Hold-to-shoot button with nearest-live-enemy auto-aim.
- Special attack button and previous/next element controls.
- Responsive mobile game layout with iOS safe-area padding. Desktop keyboard/mouse controls remain available.
- Added a dedicated mobile-controls JavaScript module; existing PvP, networking, save and gameplay systems remain in place.

HOW TO PUBLISH THIS UPDATE
1. Download and extract the full release ZIP.
2. Open the extracted docs folder.
3. Open your existing GitHub repository and navigate to its top-level docs folder on the main branch.
4. Upload the contents of this release's docs folder into that existing docs folder, replacing files when prompted. Keep index.html, manifest.webmanifest, css/, icons/ and js/ together. Do not create docs/docs.
5. Commit the changed files to main. GitHub Pages should continue to use main /docs.
6. Wait for the Pages build to finish, then reload the site on PC and iPhone. If installed as a Home Screen app, fully close and reopen it if it continues showing cached files.

DO NOT UPLOAD TO GITHUB PAGES
The cloudflare-worker folder is not part of the public site. Keep it separate from docs/.

HOW TO USE THE MOBILE CONTROLS
- MOVE: press and drag the left virtual joystick. Direction and drag distance set movement.
- SHOOT: hold the large green button to fire. It automatically targets the nearest live enemy and switches targets as enemies are defeated.
- SPECIAL: tap once to use the equipped special. Special attacks that need a target use the same nearest-target assist.
- ELEMENT: tap ‹ or › to cycle backwards/forwards through elements you've unlocked. The current element is displayed between the buttons.
- HIDE/SHOW CONTROLS: the small button near the upper-left hides/restores the touch overlay. Your preference is stored in that browser.

PC CONTROLS
Keyboard and mouse behaviour is retained: WASD/arrow keys to move, mouse to aim, hold left mouse button to shoot, right mouse button or Space for special, number keys 1–6 to choose elements, and Q/E to cycle elements.

TURN AND NETWORKING
The Worker endpoint is already set in docs/js/06-turn-peer-lifecycle.js. Do not paste Metered credentials into the public game or change the endpoint for a normal game update. The Metered API key remains a Cloudflare Worker Secret.

IMPORTANT SCRIPT ORDER
All 12 JS files in docs/js are loaded as synchronous classic scripts in the exact order listed in docs/index.html. Do not add async/defer and do not reorder the scripts. Publish all updated docs contents, not only index.html, because the mobile update changes CSS and JavaScript too.

MOBILE TEST CHECKLIST
1. Test in portrait mode; verify the scene remains centered and the hub scrolls.
2. Start a wave and check the joystick, Shoot, Special and element buttons appear.
3. Drag the joystick in each direction and diagonally; movement should stop when you lift your thumb.
4. Hold Shoot, then lift your thumb; firing should start and stop respectively.
5. Tap Special, then test each element button.
6. Hide controls, then show them again.
7. Rotate to landscape and repeat the controls test.
8. On PC, verify keyboard and mouse controls still work and the mobile overlay does not appear.
9. Test both devices in an actual PvP session. This release has not been proven on every iOS version or real network condition.

TROUBLESHOOTING
- Controls missing on mobile: ensure you are in an active gameplay run, not the hub, pause screen or spectator view. The browser must report touch support; reload after deploying all assets.
- Controls stuck after an app switch: tap the screen again or reload. The game resets touch movement/firing when the page loses or changes state.
- Shoot aims at nearest foe rather than a precise manually selected target: this is intentional for the current mobile control design. A separate aim stick could be added in a later update if desired.
- CSS/JS appears partly updated: confirm that every file in docs/ was uploaded and the script filenames exactly match index.html.
