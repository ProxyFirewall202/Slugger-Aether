SLUGGER NEO v0.5.3.1 HOTFIX MODULE MAP
===========================

index.html
  Page markup, PWA metadata, external dependencies, touch-control markup, and script-loading order.

css/styles.css
  Original desktop stylesheet plus responsive mobile layout, iOS safe-area support, and touch-control styling.

js/01-core-save-auth.js
  Core values, save model, save migration/merge, auth and cloud save/profile persistence.

js/02-art-assets-audio.js
  SVG sprite generation/loading and sound/music synthesis.

js/03-world-combat-simulation.js
  Enemy data/AI, wave simulation, player movement, combat, projectiles, hazards, damage and snapshots. Movement now accepts a touch-axis vector while preserving keyboard input behaviour.

js/04-rendering-hud-loop.js
  Canvas drawing, HUD, run conclusion UI and base loop declaration. The loop declaration is deliberately placed before module 10 because the original single-file script relied on function hoisting before its PvP wrapper.

js/05-upgrades-inventory-hub.js
  Upgrade tables/actions, crates, crafting, equipment and hub tab rendering.

js/06-turn-peer-lifecycle.js
  Friend ID, stable TURN Worker endpoint/config fetch, connection mode selection, PeerJS startup/restart, diagnostics and route inspection.

js/07-network-data-messages.js
  Network packet receive/send, host snapshots, PvP synchronization, chat/direct-message helpers and invitations.

js/08-pvp-lobby-cloud-social.js
  PvP lobby/readiness/loadouts and cloud friend, presence, request, chat and invite helpers.

js/09-social-ui-debug-hub.js
  Friends UI, connection diagnostics panel, developer console and main hub renderer.

js/10-pvp-hotfix-overrides.js
  Existing v0.5.1 PvP campaign/spectator/upgrade/results/network overrides, preserved as one ordered IIFE to avoid changing its closures and override order.

js/11-mobile-touch-controls.js
  Touch-device detection, analog virtual joystick, nearest-target auto-aim while shooting, special attack, unlocked-element cycling, Hide/Show controls toggle and touch-preference persistence.

js/12-input-and-startup.js
  Existing keyboard/mouse handlers, service timers, network/auth startup and main animation-frame boot. Desktop controls remain supported.

WHY CLASSIC SCRIPTS
The original game uses shared global declarations and inline HTML event handlers. Scripts are loaded synchronously in the exact order listed in index.html. Do not add async/defer or reorder them. The touch controls initialize in module 11 before the main loop starts in module 12.
